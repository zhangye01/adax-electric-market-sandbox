# ADAX 火电主体启动卡

日期：2026-06-11  
状态：待用户确认。确认前不得实现火电主体代码。

## 1. 工具用途

在现有 ADAX 统一虚拟省级市场中，新增“火电主体”的训练路径，让用户以火电发电主体视角经历现货市场集中竞价、十段报价、可用容量约束、训练级边际出清反馈、收益结果和复盘沉淀。

该路径用于建立“火电如何通过分段报价参与现货市场”的实操概念，不用于真实机组报价、真实现货出清、真实成本测算或经营决策。

## 2. 使用对象

- 电力市场从业新人。
- 火电企业交易、经营、计划、燃料和生产协同人员。
- 培训、咨询、研究和内部业务共识建设人员。
- 已完成或理解售电公司路径后，需要从常规电源报价主体视角理解同一虚拟市场的人。

## 3. 风险等级

风险等级：B 级，叠加部分 C 级护栏。

原因：

- 火电训练会展示报价、成本、出清、发电量、收益等经营含义，容易被误解为真实机组申报建议。
- 十段报价和边际出清容易让用户联想到真实现货规则，必须保持训练级简化。
- 所有结果必须明确“虚拟市场、训练级简化、不可用于真实交易申报或经营决策”。

## 4. Phase 5 MVP 范围

火电主体作为 Phase 5 的候选扩展。MVP 范围建议如下：

1. 继续使用同一个统一虚拟省级市场。
2. 继续保留“执行模式 / 复盘模式”两种模式。
3. 继续使用同一条交易节点链路，不为复盘模式另建一套流程。
4. 火电 MVP 只做现货市场报价训练，不新增年度双边、月度集中竞价或月内挂牌。
5. 火电路径独立于售电公司、新能源和独立储能主体实现，不复用其他主体的结算状态或业务逻辑容器。
6. 火电路径包含 8 个节点：
   - 现货市场行情与负荷环境。
   - 火电主体信息包。
   - 机组可用容量与成本区间确认。
   - 十段报价配置。
   - 申报校验与报价曲线检查。
   - 训练级集中竞价 / 边际出清反馈。
   - 发电收益与出清结果。
   - 执行结果复盘 / 复盘模式知识沉淀。
7. 行情数据使用：
   - 年度行情概览。
   - 3 个典型月。
   - 典型日 24 小时负荷、价格和供需紧张度参考。
8. 十段报价建议先按可用容量分段，不做真实机组物理约束优化。
9. 执行模式聚焦“配置报价、提交申报、看到出清反馈和结果”，提示默认隐藏，只在按钮附近或辅助入口展开。
10. 复盘模式聚焦“为什么这样分段、边际出清如何理解、成本和报价关系如何沉淀”，材料入口与执行模式提示入口保持同一位置。
11. 训练记录和复盘材料继续只保存在浏览器 localStorage。

## 5. Phase 5 明确不做什么

火电主体 MVP 不做：

- 不接入真实火电机组、真实省份、真实成本、真实报价、真实出清或真实运行记录。
- 不实现生产级现货市场出清。
- 不实现机组组合、启停成本、最小开停机时间、爬坡约束、备用约束或安全约束经济调度。
- 不实现燃料采购、煤耗曲线、环保电价、辅助服务、容量补偿或偏差考核全规则。
- 不实现多机组组合优化或报价策略竞赛。
- 不实现中长期交易。
- 不实现市场运营机构工作流。
- 不实现批发用户工作流。
- 不把火电逻辑写进售电公司、新能源或独立储能的 domain、components 或 tests 里。
- 不新增后台、登录、权限、数据库或外部 API。
- 不把复盘模式做成普通文件柜。

## 6. 输入

建议输入分为虚拟市场输入、主体输入和用户操作输入。

### 虚拟市场输入

- 市场场景：虚拟省级市场 A。
- 年度供需与价格边界。
- 典型月：沿用 3 个典型月。
- 典型日：24 小时负荷、现货价格参考和供需紧张度。
- 训练级出清窗口：建议先以一个典型日 24 小时为操作周期。

### 火电主体输入

- 主体类型：火电发电主体。
- 机组可用容量。
- 最小稳定出力。
- 报价价格边界。
- 训练级成本区间。
- 十段容量分段。
- 十段价格申报。

### 用户操作输入

- 十段报价：每段容量、申报价格。
- 报价曲线确认：是否满足单调性、容量覆盖和价格边界。
- 出清反馈确认：查看训练级成交段、边际价格和未成交段。
- 复盘材料：个人理解、规则摘录、案例材料。

## 7. 输出

执行模式输出：

- 十段报价曲线。
- 训练级成交段和未成交段。
- 训练级边际出清价格。
- 出清电量、发电收入、成本提示和结果摘要。
- 可保存的本地训练记录。

复盘模式输出：

- 按同一 8 个交易节点沉淀的文本材料。
- 每个节点的材料覆盖情况。
- 可保存的本地复盘记录。

所有输出都必须明确：结果仅用于训练理解，不代表真实市场结果，不可用于真实交易申报、机组报价、经营决策或投资决策。

## 8. 正常、边界、异常测试样例

### 正常样例

1. 火电标准执行流程
   - 输入：确认可用容量，完成十段报价，查看训练级出清反馈。
   - 预期：8 个节点可顺序完成，结果展示报价曲线、成交段、边际价格、发电收益和训练记录保存入口。

2. 火电复盘流程
   - 输入：选择复盘模式，在行情、主体信息、可用容量、十段报价、出清反馈、收益节点写入材料。
   - 预期：材料按场景、主体、节点保存；复盘记录展示材料数量和覆盖节点，不生成交易收益。

3. 单调报价曲线
   - 输入：十段价格从低到高或持平，容量合计不超过可用容量。
   - 预期：校验通过，系统展示训练级出清反馈。

### 边界样例

1. 报价容量刚好等于可用容量
   - 输入：十段容量合计等于可用容量。
   - 预期：校验通过，结果展示全部可申报容量参与训练级出清。

2. 报价容量低于可用容量
   - 输入：十段容量合计低于可用容量。
   - 预期：允许提交，但结果应展示未申报可用容量不参与出清。

3. 高价段未成交
   - 输入：后几段报价高于训练级边际价格。
   - 预期：系统展示高价段未成交，不把未成交解释为错误。

4. 低价段全部成交但收益受成本提示影响
   - 输入：低价段成交较多，但部分成交价格接近训练级成本区间。
   - 预期：系统展示收益压缩风险，不展示复杂公式作为执行模式主体验。

5. 最小稳定出力附近报价
   - 输入：前几段容量接近最小稳定出力。
   - 预期：系统提示这是训练级简化，不模拟真实机组组合和最小开机约束。

### 异常样例

1. 十段数量不完整
   - 输入：少于或多于 10 段报价。
   - 预期：校验阻断，提示需要完整十段报价。

2. 报价容量超过可用容量
   - 输入：十段容量合计超过机组可用容量。
   - 预期：校验阻断，指出容量超过可用能力。

3. 报价价格不单调
   - 输入：后一段价格低于前一段价格。
   - 预期：校验阻断或要求用户确认规则；默认建议阻断以保持训练理解清晰。

4. 报价价格超出虚拟市场边界
   - 输入：某段价格低于下限或高于上限。
   - 预期：校验阻断，不生成出清结果。

5. 必填决策缺失
   - 输入：未确认可用容量或未完成十段报价。
   - 预期：无法进入出清结果节点，提示需要先完成该交易动作。

6. 损坏的本地记录或复盘材料
   - 输入：localStorage 中存在格式损坏的火电记录。
   - 预期：页面忽略坏记录，保留可读记录，不崩溃。

7. 不支持的导入模板
   - 输入：导入售电公司、新能源、独立储能或未知主体模板到火电路径。
   - 预期：模板被拒绝，不覆盖当前火电状态。

## 9. 数据安全和文件操作风险

- 只使用虚拟市场数据和虚拟主体数据。
- 不使用真实省份、真实机组、真实成本、真实报价、真实出清或真实运行记录。
- 不上传用户数据，不调用外部 API。
- 训练记录和复盘材料仅存储在浏览器 localStorage。
- 模板导入必须先验证主体、场景、版本、字段、枚举和数值范围，再应用。
- 模板导出只生成本地文件，不覆盖用户原文件。
- 示例数据、截图和文档不得暗示真实机组收益、真实报价策略或真实经营价值。

## 10. 推荐实现步骤

确认本启动卡后，建议按以下顺序实现：

1. 先补火电 domain 启动骨架和测试，不写 UI。
   - 建议新增 `src/domain/thermalTypes.ts`。
   - 建议新增 `src/domain/thermalState.ts`。
   - 建议新增 `src/domain/thermalValidation.ts`。
   - 建议新增 `src/domain/thermalCalculations.ts`。
   - 建议新增 `src/domain/thermalExecutionChain.ts`。
2. 新增火电虚拟数据，不复用售电公司、新能源或独立储能业务数据结构。
   - 建议新增 `src/data/thermalMarketData.ts`。
   - 建议新增 `src/data/thermalTrainingNodes.ts`。
3. 先写 domain 测试。
   - 覆盖十段完整性、容量边界、价格边界、单调性、训练级出清反馈、模板拒绝。
4. 再接入主体选择页。
   - 只在火电完整工作台可用后开放可点击。
   - 未完成前不要把半成品路径暴露为可操作主流程。
5. 再实现火电工作台 UI。
   - 保持执行模式和复盘模式折叠状态下同构。
   - 执行模式显示报价操作与结果，提示默认隐藏。
   - 复盘模式同位置展示材料入口。
6. 再实现火电训练记录和复盘材料。
   - 记录必须带 `participant=thermal`。
   - 不污染售电公司、新能源或独立储能记录解释逻辑。
7. 最后做浏览器验收和 Phase 5 小结。
   - 运行 `npm run typecheck`。
   - 运行 `npm run test`。
   - 运行 `npm run build`。
   - 补充 Phase 5 审计文档。

## 11. 需要确认的问题

请在进入代码实现前确认以下问题：

1. 火电 MVP 是否只做现货十段报价？
   - 建议只做现货十段报价，不做中长期。
2. 十段报价容量是否按可用容量分段？
   - 建议按可用容量分段。
3. 十段价格是否要求单调不降？
   - 建议要求单调不降，便于训练理解。
4. 训练级出清反馈采用哪一种？
   - 建议 A：系统给出虚拟边际价格，展示成交段 / 未成交段。
   - 备选 B：系统给出虚拟需求缺口，用户自行判断成交可能性。
5. 是否展示训练级成本区间？
   - 建议展示成本提示，但执行模式不展示公式。
6. 是否确认火电作为 Phase 5 第三个候选主体？
   - 若不确认，Phase 5 可以继续保持新能源或独立储能优先，或先继续打磨售电。
