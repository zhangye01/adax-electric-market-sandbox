# ADAX 独立储能主体启动卡

日期：2026-06-11  
状态：待用户确认。确认前不得实现独立储能主体代码。

## 1. 工具用途

在现有 ADAX 统一虚拟省级市场中，新增“独立储能主体”的训练路径，让用户以独立储能运营主体视角经历现货市场参与、充放电申报、SOC 约束、执行结果、收益反馈和复盘沉淀。

该路径用于建立“储能如何参与现货市场”的实操概念，不用于优化算法训练、真实出清模拟、真实收益预测或投资决策。

## 2. 使用对象

- 电力市场从业新人。
- 独立储能项目投资、运营、交易和经营分析人员。
- 培训、咨询、研究和内部业务共识建设人员。
- 已完成或理解售电公司路径后，需要从灵活性资源视角理解同一虚拟市场的人。

## 3. 风险等级

风险等级：B 级，叠加部分 C 级护栏。

原因：

- 储能训练会展示价格、充放电、收益、偏差、SOC 等经营含义，容易被误解为真实项目收益测算。
- 独立储能与现货价格、峰谷价差和运行约束高度相关，必须明确它是训练级简化。
- 所有结果必须保持“虚拟市场、训练级简化、不可用于真实交易或投资决策”的边界说明。

## 4. Phase 5 MVP 范围

独立储能主体作为 Phase 5 的候选扩展。MVP 范围建议如下：

1. 继续使用同一个统一虚拟省级市场。
2. 继续保留“执行模式 / 复盘模式”两种模式。
3. 继续使用同一条交易节点链路，不为复盘模式另建一套流程。
4. 独立储能只参加现货市场训练，不参加年度双边、月度集中竞价或月内挂牌。
5. 独立储能路径独立于售电公司和新能源主体实现，不复用其他主体的结算状态或业务逻辑容器。
6. 独立储能路径包含 8 个节点：
   - 现货市场行情与价差环境。
   - 独立储能主体信息包。
   - 运行边界与可用能力确认。
   - 充电申报。
   - 放电申报。
   - SOC 与执行偏差检查。
   - 现货收益与运行结果。
   - 执行结果复盘 / 复盘模式知识沉淀。
7. 行情数据使用：
   - 年度行情概览。
   - 3 个典型月。
   - 典型日 24 小时现货价格曲线和系统负荷曲线。
8. 执行模式聚焦“储能主体做了哪些申报动作、受到哪些运行约束、形成什么结果”，提示默认隐藏，只在按钮附近或辅助入口展开。
9. 复盘模式聚焦“为什么选择这些时段、SOC 约束如何影响申报、价差收益如何形成”，材料入口与执行模式提示入口保持同一位置。
10. 训练记录和复盘材料继续只保存在浏览器 localStorage。

## 5. Phase 5 明确不做什么

独立储能主体 MVP 不做：

- 不接入真实储能电站、真实省份、真实价格、真实出清或真实运行记录。
- 不实现生产级现货市场出清。
- 不实现储能容量租赁、辅助服务、容量补偿、调频、备用、需求响应或绿电绿证业务。
- 不实现新能源与储能联合优化。
- 不实现电池退化、寿命折损、循环次数收益优化或项目 IRR 测算。
- 不实现多日滚动优化、随机价格预测或算法竞赛。
- 不实现市场运营机构工作流。
- 不实现批发用户工作流。
- 不把火电十段报价提前塞进储能路径。
- 不新增后台、登录、权限、数据库或外部 API。
- 不把复盘模式做成普通文件柜。
- 不把独立储能逻辑写进售电公司或新能源的 domain、components 或 tests 里。

## 6. 输入

建议输入分为虚拟市场输入、主体输入和用户操作输入。

### 虚拟市场输入

- 市场场景：虚拟省级市场 A。
- 年度供需与价格边界。
- 典型月：沿用 3 个典型月。
- 典型日：24 小时现货价格、系统负荷和供需紧张度参考。
- 现货训练窗口：建议先以一个典型日 24 小时为操作周期。

### 独立储能主体输入

- 储能类型：独立储能电站。
- 额定功率。
- 可用容量。
- 初始 SOC。
- SOC 上下限。
- 充电效率和放电效率。
- 单日可用循环约束。
- 充放电时段边界。

### 用户操作输入

- 充电申报：充电时段、充电电量或功率、申报价格。
- 放电申报：放电时段、放电电量或功率、申报价格。
- 执行修正：是否接受系统给出的训练级执行偏差或约束削减。
- 复盘材料：个人理解、规则摘录、案例材料。

## 7. 输出

执行模式输出：

- 充电、放电申报的执行状态。
- SOC 曲线和是否触及约束。
- 典型日充放电时段分布。
- 训练级价差收益、效率损耗、偏差修正和结果摘要。
- 可保存的本地训练记录。

复盘模式输出：

- 按同一 8 个交易节点沉淀的文本材料。
- 每个节点的材料覆盖情况。
- 可保存的本地复盘记录。

所有输出都必须明确：结果仅用于训练理解，不代表真实市场结果，不可用于真实交易申报、项目投资测算或经营决策。

## 8. 正常、边界、异常测试样例

### 正常样例

1. 独立储能标准执行流程
   - 输入：选择典型日，完成充电申报、放电申报和 SOC 检查。
   - 预期：8 个节点可顺序完成，结果展示充放电执行、SOC 曲线、训练级收益和训练记录保存入口。

2. 独立储能复盘流程
   - 输入：选择复盘模式，在行情、运行边界、充电、放电、SOC、收益节点写入材料。
   - 预期：材料按场景、主体、节点保存；复盘记录展示材料数量和覆盖节点，不生成交易收益。

3. 高价放电、低价充电的基础训练
   - 输入：低价时段充电，高价时段放电，申报量不超过功率和容量边界。
   - 预期：系统展示正向价差收益，同时展示效率损耗和 SOC 变化。

### 边界样例

1. 价格方向正确但 SOC 不足
   - 输入：高价时段放电申报较多，但前序充电不足。
   - 预期：系统不把价格选择正确等同于可执行，结果应提示 SOC 约束导致可执行放电不足。

2. 总充电量和总放电量接近但时段错配
   - 输入：总量看似平衡，但充电发生在高价时段，放电发生在低价时段。
   - 预期：系统展示收益压缩或负收益风险，不用公式作为执行模式主体验。

3. 到达 SOC 上限
   - 输入：连续低价时段充电，超过可用容量或 SOC 上限。
   - 预期：校验或执行修正阻断超限部分，并说明运行约束。

4. 到达 SOC 下限
   - 输入：连续高价时段放电，低于 SOC 下限。
   - 预期：校验或执行修正阻断超限部分，并说明运行约束。

5. 放弃参与某些时段
   - 输入：部分时段不申报。
   - 预期：允许不申报，但结果应展示未参与时段不产生现货收益。

### 异常样例

1. 申报功率超过额定功率
   - 输入：某小时充电或放电功率超过额定功率。
   - 预期：校验阻断，指出具体时段和字段。

2. 申报电量超过可用容量
   - 输入：单日累计充放电导致容量或 SOC 超限。
   - 预期：校验阻断或训练级执行削减，不计算完整收益。

3. 申报价格超出虚拟市场边界
   - 输入：充电或放电申报价格低于下限或高于上限。
   - 预期：校验阻断，不生成收益结果。

4. 必填决策缺失
   - 输入：未完成充电或放电申报决策。
   - 预期：无法进入结果节点，提示需要先完成该交易动作。

5. 损坏的本地记录或复盘材料
   - 输入：localStorage 中存在格式损坏的独立储能记录。
   - 预期：页面忽略坏记录，保留可读记录，不崩溃。

6. 不支持的导入模板
   - 输入：导入售电公司、新能源或未知主体模板到独立储能路径。
   - 预期：模板被拒绝，不覆盖当前独立储能状态。

## 9. 数据安全和文件操作风险

- 只使用虚拟市场数据和虚拟主体数据。
- 不使用真实省份、真实储能电站、真实报价、真实出清或真实运行记录。
- 不上传用户数据，不调用外部 API。
- 训练记录和复盘材料仅存储在浏览器 localStorage。
- 模板导入必须先验证主体、场景、版本、字段、枚举和数值范围，再应用。
- 模板导出只生成本地文件，不覆盖用户原文件。
- 示例数据、截图和文档不得暗示真实项目收益或真实投资价值。

## 10. 推荐实现步骤

确认本启动卡后，建议按以下顺序实现：

1. 先补独立储能 domain 启动骨架和测试，不写 UI。
   - 建议新增 `src/domain/storageTypes.ts`。
   - 建议新增 `src/domain/storageState.ts`。
   - 建议新增 `src/domain/storageValidation.ts`。
   - 建议新增 `src/domain/storageCalculations.ts`。
   - 建议新增 `src/domain/storageExecutionChain.ts`。
2. 新增独立储能虚拟数据，不复用售电公司或新能源业务数据结构。
   - 建议新增 `src/data/storageMarketData.ts`。
   - 建议新增 `src/data/storageTrainingNodes.ts`。
3. 先写 domain 测试。
   - 覆盖功率边界、容量边界、SOC 上下限、效率损耗、价格边界、模板拒绝。
4. 再接入主体选择页。
   - 只在独立储能完整工作台可用后开放可点击。
   - 未完成前不要把半成品路径暴露为可操作主流程。
5. 再实现独立储能工作台 UI。
   - 保持执行模式和复盘模式折叠状态下同构。
   - 执行模式显示操作与结果，提示默认隐藏。
   - 复盘模式同位置展示材料入口。
6. 再实现独立储能训练记录和复盘材料。
   - 记录必须带 `participant=storage`。
   - 不污染售电公司或新能源记录解释逻辑。
7. 最后做浏览器验收和 Phase 5 小结。
   - 运行 `npm run typecheck`。
   - 运行 `npm run test`。
   - 运行 `npm run build`。
   - 补充 Phase 5 审计文档。

## 11. 需要确认的问题

请在进入代码实现前确认以下问题：

1. 独立储能训练周期采用哪一种？
   - 建议 A：一个典型日 24 小时。
   - 备选 B：3 个典型日分别训练。
   - 备选 C：3 个典型月各选一个典型日。
2. 充放电申报粒度采用哪一种？
   - 建议 A：24 小时逐小时申报。
   - 备选 B：峰 / 平 / 谷时段包申报。
   - 备选 C：系统给定时段包，用户只填电量和价格。
3. 是否允许同一小时同时出现充电和放电申报？
   - 建议不允许。
4. 现货执行结果采用哪一种？
   - 建议 A：训练级成交 / 未成交 / 部分成交状态。
   - 备选 B：只按用户申报生成执行结果，不模拟成交状态。
5. 是否需要展示效率损耗？
   - 建议需要，但执行模式只展示结果，不展示公式。
6. 是否确认独立储能作为 Phase 5 的第二个候选主体？
   - 若不确认，Phase 5 可以继续保持新能源优先，或先继续打磨售电。
