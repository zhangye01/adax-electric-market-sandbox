# ADAX 新能源主体启动卡

日期：2026-06-10  
状态：待用户确认。确认前不得实现新能源主体代码。

## 1. 工具用途

在现有 ADAX 统一虚拟省级市场中，新增“新能源主体”的训练路径，让用户以新能源发电主体视角经历中长期交易组织、月内挂牌、出力曲线与现货偏差、结算反馈和复盘沉淀。

该路径用于建立电力市场交易实操概念，不用于考核复杂策略水平，也不模拟真实交易申报、真实结算或真实省份规则。

## 2. 使用对象

- 电力市场从业新人。
- 新能源发电企业业务、交易、经营分析人员。
- 培训、咨询、研究和内部业务共识建设人员。
- 已完成或理解售电公司路径后，需要从发电侧主体理解同一虚拟市场的人。

## 3. 风险等级

风险等级：B 级，叠加部分 C 级护栏。

原因：

- 该工具会被固定用户群体重复用于培训和业务理解，属于小范围复用工具。
- 输出包含价格、收益、偏差、风险等金融或经营含义，容易被误解为真实交易建议。
- 因此所有结果必须保持“虚拟市场、训练级简化、不可用于真实交易决策”的边界说明。

## 4. Phase 5 MVP 范围

新能源主体作为 Phase 5 的第一个候选扩展。MVP 范围建议如下：

1. 继续使用同一个统一虚拟省级市场。
2. 继续保留“执行模式 / 复盘模式”两种模式。
3. 继续使用同一条交易节点链路，不为复盘模式另建一套流程。
4. 新能源主体独立于售电公司主体实现，不复用售电公司的结算状态或 UI 节点组件作为业务逻辑容器。
5. 新能源路径包含 8 个节点：
   - 市场行情与新能源出力环境。
   - 新能源主体信息包。
   - 年度双边交易。
   - 月度集中竞价。
   - 月内挂牌交易。
   - 现货偏差与曲线错配。
   - 结算结果。
   - 执行结果复盘 / 复盘模式知识沉淀。
6. 中长期交易包含 3 次：
   - 年度双边。
   - 月度集中竞价。
   - 月内挂牌。
7. 行情数据使用：
   - 年度行情。
   - 3 个典型月。
   - 典型日 24 小时曲线。
8. 执行模式聚焦“做了哪些交易动作、动作产生什么结果”，提示默认隐藏，只在按钮附近或辅助入口展开。
9. 复盘模式聚焦“为什么这样做、规则和材料如何沉淀”，材料入口与执行模式提示入口保持同一位置。
10. 训练记录和复盘材料继续只保存在浏览器 localStorage。

## 5. Phase 5 明确不做什么

新能源主体 MVP 不做：

- 不接入真实新能源电站、真实省份、真实出力、真实价格或真实交易记录。
- 不实现真实现货市场出清。
- 不实现生产级功率预测模型。
- 不实现绿电、绿证、容量补偿、辅助服务、偏差考核全规则。
- 不实现新能源与储能联合优化。
- 不实现市场运营机构工作流。
- 不实现批发用户工作流。
- 不把火电十段报价提前塞进新能源路径。
- 不新增后台、登录、权限、数据库或外部 API。
- 不把复盘模式做成普通文件柜。
- 不把新能源逻辑写进售电公司的 domain、components 或 tests 里。

## 6. 输入

建议输入分为虚拟市场输入、主体输入和用户操作输入。

### 虚拟市场输入

- 市场场景：虚拟省级市场 A。
- 年度供需与价格边界。
- 典型月：建议沿用 3 个典型月。
- 典型日：24 小时价格、负荷、出力参考曲线。
- 月内挂牌窗口：建议以典型日时段或时段包表达。

### 新能源主体输入

- 主体类型：待确认，建议默认“风光组合”。
- 年度预计上网电量。
- 典型月预计出力。
- 典型日 24 小时出力曲线。
- 可交易电量边界。
- 合约曲线或时段标的选项。

### 用户操作输入

- 年度双边交易：交易电量、交易价格、合约曲线。
- 月度集中竞价：参与 / 不参与、交易电量、申报价格、合约曲线。
- 月内挂牌：挂牌时段、挂牌电量、挂牌价格、是否成交。
- 复盘材料：个人理解、规则摘录、案例材料。

## 7. 输出

执行模式输出：

- 年度、月度、月内三类交易的成交状态。
- 合约电量与预测出力的关系。
- 24 小时时段上的合约曲线与出力曲线错配。
- 现货偏差或敞口方向。
- 训练级收益、偏差风险和结算摘要。
- 可保存的本地训练记录。

复盘模式输出：

- 按同一 8 个交易节点沉淀的文本材料。
- 每个节点的材料覆盖情况。
- 可保存的本地复盘记录。

所有输出都必须明确：结果仅用于训练理解，不代表真实市场结果，不可用于真实交易申报或投资决策。

## 8. 正常、边界、异常测试样例

### 正常样例

1. 新能源标准执行流程
   - 输入：风光组合主体，完成年度双边、3 个典型月月度集中竞价、一次月内挂牌。
   - 预期：8 个节点可顺序完成，结算结果展示成交电量、现货偏差、风险提示和训练记录保存入口。

2. 新能源复盘流程
   - 输入：选择复盘模式，在年度双边、月度集中竞价、月内挂牌三个节点分别写入材料。
   - 预期：材料按场景、主体、节点保存；复盘记录展示材料数量和覆盖节点，不生成交易收益。

3. 交易链路一致性
   - 输入：同一场景下分别进入执行模式和复盘模式。
   - 预期：节点顺序一致，主界面结构一致；差异只体现在执行提示和复盘材料入口。

### 边界样例

1. 总量接近匹配但曲线错配
   - 输入：合约总电量接近预测出力总量，但 24 小时曲线明显不一致。
   - 预期：系统仍展示现货偏差或曲线错配风险，不能把“总量一致”解释为“无风险”。

2. 月度集中竞价选择不参与
   - 输入：某典型月选择不参与，隐藏交易电量和价格。
   - 预期：校验允许该月不参与，但不允许隐藏字段残留无效交易数据。

3. 月内挂牌只覆盖部分时段
   - 输入：只对高价或低出力时段挂牌。
   - 预期：系统允许部分时段操作，并在结果中展示未覆盖时段的敞口。

4. 高出力低价格典型日
   - 输入：新能源高出力时段对应低现货价格。
   - 预期：系统能展示低价暴露或收益压缩风险，但不使用真实省份机制语言。

### 异常样例

1. 交易电量超过可交易边界
   - 输入：年度、月度或月内电量超过主体可交易上限。
   - 预期：校验阻断，指出具体交易节点和字段。

2. 申报价格超出虚拟市场价格边界
   - 输入：年度、月度或月内价格低于下限或高于上限。
   - 预期：校验阻断，不计算结算结果。

3. 必填决策缺失
   - 输入：未选择月度集中竞价参与 / 不参与。
   - 预期：无法进入结算，提示需要先完成该交易决策。

4. 损坏的本地记录或复盘材料
   - 输入：localStorage 中存在格式损坏的新能源记录。
   - 预期：页面忽略坏记录，保留可读记录，不崩溃。

5. 不支持的导入模板
   - 输入：导入售电公司模板或未知主体模板到新能源路径。
   - 预期：模板被拒绝，不覆盖当前新能源状态。

## 9. 数据安全和文件操作风险

- 只使用虚拟市场数据和虚拟主体数据。
- 不使用真实省份、真实电站、真实客户、真实报价或真实成交记录。
- 不上传用户数据，不调用外部 API。
- 训练记录和复盘材料仅存储在浏览器 localStorage。
- 模板导入必须先验证主体、场景、版本、字段、枚举和数值范围，再应用。
- 模板导出只生成本地文件，不覆盖用户原文件。
- 示例数据、截图和文档不得暗示真实市场收益或真实交易建议。

## 10. 推荐实现步骤

确认本启动卡后，建议按以下顺序实现：

1. 先补新能源 domain 启动骨架和测试，不写 UI。
   - 建议新增 `src/domain/renewableTypes.ts`。
   - 建议新增 `src/domain/renewableState.ts`。
   - 建议新增 `src/domain/renewableValidation.ts`。
   - 建议新增 `src/domain/renewableCalculations.ts`。
   - 建议新增 `src/domain/renewableExecutionChain.ts`。
2. 新增新能源虚拟数据，不复用售电公司业务数据结构。
   - 建议新增 `src/data/renewableMarketData.ts`。
   - 建议新增 `src/data/renewableTrainingNodes.ts`。
3. 先写 domain 测试。
   - 覆盖年度双边、月度集中竞价、月内挂牌、曲线错配、结算边界、模板拒绝。
4. 再接入主体选择页。
   - 只在新能源完整工作台可用后开放可点击。
   - 未完成前不要把半成品路径暴露为可操作主流程。
5. 再实现新能源工作台 UI。
   - 保持左侧操作、中间市场视图、右侧结果反馈的结构。
   - 执行模式和复盘模式折叠状态下保持同构。
6. 再实现新能源训练记录和复盘材料。
   - 记录必须带 `participant=renewable`。
   - 不污染售电公司记录解释逻辑。
7. 最后做浏览器验收和 Phase 5 小结。
   - 运行 `npm run typecheck`。
   - 运行 `npm run test`。
   - 运行 `npm run build`。
   - 补充 Phase 5 审计文档。

## 11. 需要确认的问题

请在进入代码实现前确认以下问题：

1. 新能源主体类型采用哪一种？
   - 建议 A：风光组合。
   - 备选 B：仅光伏。
   - 备选 C：仅风电。
2. 月内挂牌的操作粒度采用哪一种？
   - 建议 A：界面展示 24 小时曲线，操作按峰 / 平 / 谷时段包。
   - 备选 B：直接按 24 小时逐小时挂牌。
   - 备选 C：只做一个月内总量挂牌，不细化时段。
3. 月度集中竞价是否继续采用 3 个典型月？
   - 建议沿用现有售电主线的 3 个典型月，便于同一市场背景下对比。
4. 新能源年度双边是否也设置模拟对手方接受条件？
   - 建议设置最低可接受价格或成交区间，但不做复杂撮合。
5. 月内挂牌是否需要“挂牌未成交”的训练结果？
   - 建议需要，否则月内挂牌会变成普通补充交易，缺少交易动作感。
6. 是否确认新能源作为 Phase 5 第一个实现主体？
   - 若不确认，Phase 5 可以改为继续打磨售电，或先为独立储能写启动卡。

## 12. 工程准入条件

进入代码实现前必须满足：

- 用户确认本启动卡。
